# LineagePilot rules

LineagePilot checks every dbt node against these rules and shows the results in the
Problems panel. Each diagnostic links to its rule below.

Every check has one of five results: **pass**, **fail**, **not applicable**,
**unsupported** (LineagePilot cannot make this check) or **unknown** (the facts it needs
are missing, for example column lineage). Failures are shown with the rule's severity;
unknown results are shown as information ("Not checked"), never as passes. The score
counts only passes and failures, and coverage, shown beside it, says how much could be
checked.

PII rules report *indicators*, from tags, column names and lineage, not verified
exposure.

Add, disable or re-grade rules in `.lineagepilot/rules.yml` at the project root. Custom
rules are not loaded in Restricted Mode.

This file is generated by `packages/core/scripts/rules_doc.py`.

### MED_001

**Gold sources Silver only**. Gold/Mart layer models should only source from Silver/Intermediate layers

- Severity: error
- Category: lineage
- Checks: each model
- Fix: Refactor to source from Silver/Intermediate layer instead of Bronze/Raw

### MED_002

**Silver sources Bronze only**. Silver/Intermediate models should only source from Bronze/Raw or other Silver

- Severity: warning
- Category: lineage
- Checks: each model
- Fix: Ensure Silver models source from Bronze/Raw or other Silver models

### MED_003

**Bronze naming convention**. Bronze/Raw layer models should follow naming convention

- Severity: warning
- Category: naming
- Checks: each model
- Fix: Rename model to start with raw_, bronze_, stg_, or src_

### MED_004

**Silver naming convention**. Silver/Intermediate models should follow naming convention

- Severity: warning
- Category: naming
- Checks: each model
- Fix: Rename model to start with int_, silver_, or stg_

### MED_005

**Gold naming convention**. Gold/Mart models should follow naming convention

- Severity: warning
- Category: naming
- Checks: each model
- Fix: Rename model to start with dim_, fct_, fact_, mart_, rpt_, or gold_

### DBT_001

**Model has description**. All models should have a description

- Severity: warning
- Category: documentation
- Checks: each model
- Fix: Add a description in the schema.yml file

### DBT_002

**Model has tests**. All models should have at least one test

- Severity: warning
- Category: testing
- Checks: each model
- Fix: Add at least one test (unique, not_null, etc.) in schema.yml

### DBT_003

**Model naming snake_case**. Model names should be in snake_case

- Severity: info
- Category: naming
- Checks: each model
- Fix: Rename model to use snake_case (lowercase with underscores)

### DBT_004

**Column has description**. Columns should have descriptions

- Severity: info
- Category: documentation
- Checks: each column of each model
- Fix: Add a description for this column in schema.yml

### PII_001

**PII in Gold must be masked**. PII columns in Gold/Mart layer should be masked, hashed, or encrypted

- Severity: critical
- Category: pii
- Checks: each column of each model, seed, snapshot, source
- Fix: Apply masking, hashing, or encryption to this PII column

### PII_002

**PII columns must be tagged**. Columns containing PII should have explicit PII tags

- Severity: error
- Category: pii
- Checks: each column of each model, seed, snapshot, source
- Fix: Add PII tag via meta: {pii: true, pii_type: ...} in schema.yml

### PII_003

**PII type should be specified**. PII columns should have specific PII type classification

- Severity: warning
- Category: pii
- Checks: each column of each model, seed, snapshot, source
- Fix: Specify PII type (email, phone, ssn, etc.) in meta

### DBT_005

**Model has a primary key**. Every model should have a primary key: a column with unique and not_null tests, or a contract primary-key constraint

- Severity: error
- Category: structural
- Checks: each model
- Fix: Add unique and not_null tests to the key column, or a primary_key constraint
- Replaces the Data Capsule rule: DIM2_006
