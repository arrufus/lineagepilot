# lineagepilot-lsp

The LineagePilot language server: `lineagepilot_core` behind the Language Server Protocol, over stdio (design sections 4 and 9). The VS Code extension in `extension/` starts one server per dbt project, from the copy bundled in its VSIX.

## What it does

- **Indexes in a child process** (`worker.py`): the model-level graph first, then column lineage, each handed over as a snapshot in the cache directory. The server never parses on its event loop, and freezes its heap after each load (design section 11).
- **Watches** the artifacts, `dbt_project.yml`, the project's source files, `.lineagepilot/rules.yml` and the DAG folders through `workspace/didChangeWatchedFiles`, with debouncing.
- **LSP features**: CodeLens, hover and diagnostics (`features.py`).
- **`lineage/*` requests** (`methods.py`): `status`, `refresh`, `graph`, `impact`, `export`, `nodesForFile`, and the `indexUpdated` notification. Params are validated against the shared schema in `protocol/` (`protocol.py` is generated from it).

## Modules

| Module | |
|---|---|
| `server.py` | The pygls server: initialise and protocol negotiation, handlers, diagnostics publishing, logging to the client |
| `indexing.py` | The index state machine for one project, the indexer process, staleness |
| `worker.py` | The indexer, run as a child process |
| `context.py` | Everything derived from one loaded graph, and column lineage on demand |
| `features.py` | CodeLens, hover and diagnostics |
| `methods.py` | The `lineage/*` requests |
| `locate.py` | Files and positions: where a node or column is declared in YAML |
| `project.py` | `dbt_project.yml`, read as untrusted input |
| `watch.py` | What is watched, what each change means, and the debouncer |
| `protocol.py` | Generated by `protocol/generate.py`; do not edit |

## Development

```bash
cd packages/lsp
uv sync --locked
uv run --locked pytest                          # unit and end-to-end tests, coverage gate 80%
uv run --locked ruff check . && uv run --locked ruff format --check .
python ../../protocol/generate.py --check        # after changing protocol/lineage-protocol.schema.json
```

The end-to-end tests start the server with `python -I -m lineagepilot_lsp` and talk to it over stdio with pytest-lsp, on a copy of `fixtures/jaffle-shop`. To run them against the VSIX's bundled server on interpreters with nothing installed:

```bash
LP_TEST_SERVER=../../extension/bundled/tool/lsp_server.py LP_TEST_PYTHONS=/path/to/python3.10:/path/to/python3.13 \
  uv run --locked pytest --no-cov tests/test_indexing_e2e.py tests/test_methods_e2e.py tests/test_features_e2e.py
```

The server writes nothing to stdout but LSP messages. Its logging goes to the client as `window/logMessage`, and to stderr for warnings and errors.
